# 📘 كتالوج التحديث الشامل — تطبيق أكاديمية النخبة (Flutter + Supabase)

> **تنبيه صريح:** بيئة العمل اللي اتعدّل فيها المشروع **مفيهاش Flutter SDK ولا PostgreSQL**، فالكود **ماتعملّوش Compile ولا Run**، والـ SQL **ماتنفّذش على قاعدة بيانات حقيقية**. اتعملت فحوصات ثابتة (توازن الأقواس، مطابقة الـ imports، مطابقة الـ placeholders في الترجمة، مقارنة التغييرات مع النسخة اللي بعتّها). أول خطوة عندك: `flutter pub get` ثم `flutter analyze` ثم شغّل السكربت على Supabase جديد/تجريبي (التفاصيل في دليل التشغيل).

## 2) الـ Backend (قاعدة البيانات)

### الجديد في 02 (على اللي كان موجود)
* `check_signup_code(code)` — بتتأكد من الكود **قبل** إنشاء حساب Auth (متصلة بـ anon) فمفيش حسابات يتيمة.
* `complete_signup()` — بعد ما المستخدم يأكد الإيميل (حيث مفيش Session وقت التسجيل) بتبني البروفايل من `raw_user_meta_data`. **الدور بيتحدد من الكود فقط** (admin/coach/player)، العميل مبيبعتش دور أبداً.
* أكواد الدعوة بقت **8 خانات** بدل 6 (≈ 10¹² احتمال بدل 10⁹) لتقليل التخمين.

### مصفوفة الصلاحيات (RLS) باختصار
| الجدول | قراءة | كتابة |
|--------|-------|-------|
| academies | أكاديميتك فقط | الأدمن |
| users | نفسك، أو الأدمن/المدرب لمستخدمي أكاديميتهم | تعديل نفسك (الاسم/التليفون/العنوان/الصورة فقط — Trigger يمنع الدور/الأكاديمية/الإيميل) |
| coaches, teams | كل أعضاء الأكاديمية | الأدمن |
| players, trainings, matches, tournaments, standings, reports, notifications | كل الأعضاء | الأدمن + المدرب (اللاعب يعدّل صفّه بحدود) |
| attendance | الأدمن/المدرب الكل، واللاعب حضوره هو فقط | الأدمن + المدرب |
| notification_reads | حالة القراءة **لكل مستخدم** | نفسك فقط |
| academy_codes | **محدش** (RPC فقط) | — |

## 3) آلية التحقق بالإيميل (Flow)

```
تسجيل جديد ─► check_signup_code / academy_name_available   (قبل أي حساب)
          ─► auth.signUp(email, password, data{name,phone,address,academy_code|new_academy_name})
              ├─ Confirm email = OFF  → session موجودة → rpc complete_signup → داشبورد
              └─ Confirm email = ON   → مفيش session → شاشة VerifyEmailScreen
                                         المستخدم يكتب الكود (6 أرقام) من Gmail
                                         → auth.verifyOTP(type: signup) → rpc complete_signup → داشبورد
تسجيل دخول لحساب غير مؤكد ─► شاشة VerifyEmailScreen (بيتبعت كود جديد تلقائياً)
نسيت كلمة المرور ─► ForgotPasswordScreen(إيميل) → auth.resetPasswordForEmail
                  ─► ResetPasswordScreen(الكود + الباسورد الجديد)
                     → auth.verifyOTP(type: recovery) → auth.updateUser(password) → signOut → تسجيل دخول
```
* **ليه OTP مش لينك؟** اللينك محتاج Deep Links (Android/iOS config) وبيتكسر لو الجهاز مفيهوش التطبيق. الكود بيشتغل في أي حالة.
* **Gmail:** الـ Validator بيرفض الأخطاء الشائعة (`gmial.com`…) والإيميلات المؤقتة (`mailinator`…). الإيميل "الحقيقي" بيتأكد فعلياً بإن الكود وصله.

## 4) الترجمة (عربي ⇄ إنجليزي)

**الفكرة:** لغة المصدر عربي. `Text` في `lib/l10n/app_text.dart` بيستبدل `Text` بتاع Flutter (نفس الـ constructor و`const`)، وبيترجم وقت العرض من القاموس لو اللغة English.
* الاتجاه: `AppDirectionality` بتستبدل كل `Directionality(textDirection: rtl)` (46 موضع) وبتتبع اللغة؛ شلنا `TextDirection.rtl` الثابتة من باقي الـ widgets (54 موضع) لأن الاتجاه بيتوارث. `TextAlign.right → start` (38 موضع) — **مطابق بصرياً في العربي**.
* التحديث الفوري: `Text` و`AppDirectionality` معتمدين على `Localizations` اللي بتتغير مع `MaterialApp(locale:)` فبيتعاد بناؤهم تلقائياً حتى جوه الـ const subtrees. مفيش إعادة تشغيل ولا فقد للـ navigation stack.
* الـ hints والـ validators بتعدّي على `L10n.trN / L10n.tr`.
* ترتيب الترجمة: تطابق تام ← قوالب بمتغيرات (مثل `{} لاعب`) ← استبدال عبارات على حدود الكلمات (مع ذاكرة تخزين مؤقت).
* **أضف ترجمة لنص جديد:** أضف سطر في `tools/extra_en.txt` بصيغة `النص العربي => English` ثم `cd tools && python3 gen_dict.py` **أو** أضف السطر مباشرة في `lib/l10n/en_dictionary.dart` (`kEn`).
* **حدود معروفة:** أسماء ولاعبين/فرق مكتوبة عربي (بيانات مستخدم) هتفضل عربي في الوضع الإنجليزي. نصوص ثابتة داخل `TextSpan`/`RichText` لا تُترجم. أي رسالة تتكوّن بدمج جمل من أكتر من literal ممكن تترجم جزئياً (التطبيق بيستبدل العبارات المعروفة منها). مفيش مراجعة بصرية على الجهاز لتخطيطات الـ LTR — **جرّب كل شاشة بالإنجليزي**.

## 6) الأعطال اللي اتصلحت (من مراجعة النسخة اللي بعتّها)
1. شاشة "نسيت كلمة المرور" كانت **محاكاة** (رقم تليفون + كود وهمي 4 أرقام) ← إيميل حقيقي + OTP.
2. مفيش تحقق من الإيميل أصلاً، والتسجيل بيفترض session فورية (بيفشل لو Confirm email مفعّل) ← مسار كامل + `complete_signup`.
3. **مفيش أي واجهة لإنشاء مباراة** (الـ backend كان موجود، الشاشة بتعرض بس) ← CRUD كامل.
4. حذف الحساب: الـ RPC موجود والنص في الخصوصية بيوعد بيه بس مفيش زرار ← اتضاف.
5. بطولات: مفيش تعديل/حذف؛ ترتيب: مفيش حذف ← اتضافوا.
6. الاتجاه RTL كان مكتوب ثابت في 100 موضع ← بقى تابع للغة.
7. أكواد الدعوة 6 خانات ← 8.
8. `check_signup_code` ناقصة لمنع حسابات Auth اليتيمة ← اتضافت.
9. **Android release بدون صلاحية `INTERNET`** (موجودة في debug فقط) ← اتضافت في `android/app/src/main/AndroidManifest.xml`.
10. **iOS: `NSPhotoLibraryUsageDescription` ناقص** (Crash عند اختيار صورة) ← اتضاف في `ios/Runner/Info.plist`.

## 7) قيود/مخاطر معروفة (بصراحة)
* **`check_signup_code` مفتوحة لـ anon** عشان التحقق المسبق → ممكن تتستخدم في تخمين الأكواد. الـ 8 خانات بتصعّب الموضوع جداً، وفعّل Rate Limits في Supabase. لو عايز أمان أعلى: انقلها لـ Edge Function بحد لكل IP.
* أكواد الأدمن (`admin_code`) بتسمح بأكتر من أدمن لنفس الأكاديمية — ده تصميم النسخة اللي اتبعتت (والنص في التسجيل بيقول العكس). قرّر وعدّل `join_academy`.
* الكود ماتعملّوش Compile: راجع `flutter analyze`. أكتر نقاط محتاجة عين: `Localizations.maybeLocaleOf` (يحتاج Flutter ≥ 3.7)، و`AuthException.code` (يحتاج `supabase_flutter ≥ 2.8` — موجود في الـ pubspec).
* أحجام الـ OTP: Supabase بيرسل 6 أرقام افتراضياً. الشاشات بتقبل 6–8.
* رسائل الإيميل الافتراضية من Supabase **محدودة جداً** ولا تصلح للإنتاج → لازم SMTP مخصص (Gmail App Password أو خدمة مثل Resend/Brevo).

## 8) دليل استكشاف الأخطاء

| العَرَض | السبب المحتمل | الحل |
|---------|----------------|------|
| الكود مش بيوصل على Gmail | SMTP مش متظبط / رسائل Supabase الافتراضية محدودة / Spam | اتبع دليل التشغيل خطوة 3؛ شوف **Authentication → Logs** و**Spam**؛ اتأكد إن الـ App Password صح بدون مسافات |
| `email rate limit exceeded` | حد الإرسال في الساعة | Authentication → Rate Limits؛ استنى 60 ثانية بين الإرسالات |
| "الكود غلط أو منتهي" | كود قديم أو مكتوب غلط أو قالب الإيميل مفيهوش `{{ .Token }}` | اطلب كود جديد؛ راجع القالب (لو الرسالة فيها لينك بس → القالب لسه الافتراضي) |
| بعد التأكيد: "حصل خطأ" وبدون دخول | `complete_signup` فشلت (اسم أكاديمية مكرر/كود غلط) أو SQL ما اتنفذش | شغّل `select public.complete_signup();` كمستخدم مسجّل؛ راجع Logs > Postgres |
| `function ... does not exist` (PGRST202) | ملفات SQL مش كلها اتنفذت أو cache للـ schema | نفّذ `FULL_SETUP.sql` كامل ثم `notify pgrst, 'reload schema';` |
| `permission denied for table` / `new row violates row-level security` | سياسة RLS ناقصة أو المستخدم من غير بروفايل | تأكد إن `users` فيها صفك؛ راجع الجدول في §2 |
| صفحات فاضية بعد الدخول | بروفايل ناقص (signup اتقطع) | سجّل دخول مرة تانية (بيكمل تلقائياً) أو احذف مستخدم Auth وسجّل من جديد |
| اللغة اتغيّرت وفيه نص لسه عربي | نص ما اتضافش للقاموس أو بيانات مستخدم | أضفه في `extra_en.txt` وولّد القاموس؛ أو شغّل الفحص: ابحث عن النص الحرفي في `en_dictionary.dart` |
| خطأ compile: `ambiguous import Text` | ملف بيستورد `widgets.dart`/`cupertino.dart` مع `app_text.dart` | استخدم `import 'package:flutter/material.dart' hide Text;` ولا تستورد widgets/cupertino للـ Text |
| خطأ compile في `Text` بباراميتر جديد | الـ Text البديل بيدعم باراميترات Flutter القياسية فقط | أضف الباراميتر في `lib/l10n/app_text.dart` |
| الصور مش بتترفع | bucket `avatars` غير موجود/السياسات | شغّل قسم 6 في `02_security_rpc.sql` أو أنشئ bucket عام باسم `avatars` من Storage |
| بعد `00_reset.sql` الحسابات القديمة بتدخل بدون بروفايل | مسحنا الجداول مش `auth.users` | سجّل دخول (بيكمل البروفايل لو الـ metadata موجودة) أو امسح المستخدمين من Authentication > Users |
